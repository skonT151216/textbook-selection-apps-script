학교 담당자가 Google Apps Script와 스프레드시트에 설치하고, 선생님에게 학교 아이디를 발급합니다. 일반 선생님은 별도 프로그램 설치 없이 웹 앱 주소에서 본인 아이디로 접속합니다.

### 2026-10-02 저장 용량 개선과 정상 저장본 보호

r14는 학교 전체 자료에 적용되던 90만 문자 제한을, 중복을 제거한 저장 자료 기준 800만 문자로 변경합니다. 완전히 같은 서명 이미지와 현재 대상의 중복 자료만 묶어 저장하며, 읽을 때 기존 형태로 복원합니다. 서명 이미지를 재압축하거나 줄이지 않고 점수·의견·이름·서명 시각·계정 기록을 유지합니다.

새 내용은 별도 저장칸에 기록하고 다시 읽어 체크섬과 원본 내용의 일치를 확인한 뒤 사용합니다. 기록이나 검증이 실패하면 새 저장칸으로 전환하지 않습니다. 전환 전 정상본도 한 세대 보관하며 기존 `_APP_DATA`는 업데이트 전 자료로 남깁니다. 저장본 손상이 발견되면 빈 자료로 시작하거나 오래된 자료로 자동 대체하지 않고 오류로 중단합니다.

업데이트 전에 교사들의 저장 작업을 잠시 멈추고 데이터 스프레드시트 전체를 사본으로 백업하세요. 세 설치 파일을 교체하고 새 버전으로 배포하면 첫 정상 저장 시 자동으로 새 형식으로 전환됩니다. 초기화·재서명은 필요하지 않습니다. `_APP_DATA`, `_APP_DATA_V2_A`, `_APP_DATA_V2_B`와 스크립트 속성 `WORKSPACE_SNAPSHOT_V1`은 삭제하지 마세요. 전환 후 구버전 코드만 덮어쓰면 최신 자료를 읽지 못하므로, 문제가 생기면 먼저 현 상태를 보존하고 [복구 주의사항](상세_실행_매뉴얼.md)을 확인하세요.

### 2026-10-01 추천의견서 작성자 서명 저장 수정

r13은 추천의견 문구가 같은데 내부 데이터 항목 순서만 달라진 경우를 내용 변경으로 오인해, 방금 저장한 작성자 서명을 지우던 문제를 수정합니다. 직접 서명과 이미지 첨부 모두 같은 수정이 적용됩니다. 화면의 서명 가능 여부와 자동 의견 생성에서도 항목 순서가 아닌 실제 내용을 비교합니다. 별도의 확인 장치나 추가 조작은 넣지 않았습니다.

기존 평가자료를 초기화할 필요는 없습니다. 이미 정상 저장된 서명은 유지되며, 이전 오류로 사라진 서명 이미지는 자동 복원되지 않으므로 업데이트 후 해당 서명만 다시 입력하세요. 추천의견 문구를 실제로 수정해 저장하면 서명을 다시 받는 기존 정책은 유지됩니다.

### 2026-09-29 개인별 평가표에 선정 대상명 표시

r12부터 **업무 설정 → 선정 방식**에서 `개인별 평가표에 선정 대상명 표시`를 켜거나 끌 수 있습니다. 켜면 `선정 대상명별로 따로 평가`하는 교과의 서식 1 상단에 `교과: 국어`와 `선정 대상: 언어생활 탐구 3-1`이 함께 표시됩니다. 작성 화면의 출력 미리보기, 개별 PDF, 묶음 PDF, 가상 서식 테스트에 적용됩니다. 기존 도서별 선정 학교는 표시가 기본으로 켜지며, 다른 선정 방식의 서식은 기존 표시를 유지합니다. 이 설정을 바꿔도 평가 점수·의견·서명은 유지됩니다.

### 2026-09-29 평가 중인 교과가 있어도 다른 설정 저장

r11에서는 평가 중인 교과의 도서나 후보 구성이 달라진 경우에도 설정 저장 전체가 실패하지 않습니다. 해당 교과의 도서·선정 방식·후보는 이전 상태로 유지하고, 학교 정보·교직원·다른 교과의 변경은 저장합니다. 변경을 보류한 교과가 있으면 저장 직후 그 이름을 안내합니다. 따라서 그 교과의 새 도서나 후보가 실제로 반영된 것으로 착각하지 않도록 저장된 설정을 확인하세요. 기존 평가와 서명은 유지됩니다. 평가 중인 교과의 후보 자체를 바꾸는 절차는 별도 초기화·재평가가 필요합니다.

### 2026-09-29 업무 설정 저장 차단 수정

r10은 기존 평가가 있는 선정 단위를 보존하면서 교직원·학교 정보 등 다른 설정을 저장할 수 있도록 고쳤습니다. r9에서 기존 단위에 없던 `선정 대상명`의 빈 값을 변경으로 오인하던 비교를 바로잡았습니다. 협의회에서 교사를 제외하더라도 이미 작성된 평가는 기록으로 유지하며, 현재 평가 집계에서는 제외합니다. 설정 저장 중 기존 평가·추천의견·서명이 우발적으로 사라지지 않도록 서버에서도 보호합니다. 실제로 평가가 시작된 단위의 후보나 선정 방식을 바꾸는 작업은 계속 차단됩니다.

기존 평가를 초기화하거나 다시 서명할 필요는 없습니다. 업데이트 전 스프레드시트를 백업하고 세 파일을 교체한 뒤 새 웹 앱 버전으로 배포하세요.

### 2026-09-29 여러 교과의 도서별 선정 지원

r9에서는 어느 교과든 도서 목록의 **선정 대상명**에 따라 평가 대상을 여러 개로 나눌 수 있습니다. 엑셀 업로드 시 도서명을 대상명 기본값으로 사용하며, 출판사마다 도서명 표기가 다르면 도서·가격 표에서 같은 대상명으로 수정하세요. 엑셀에 `선정 대상명` 열을 추가해 직접 지정해도 됩니다. 선정 방식 단계에서 **선정 대상명별로 따로 평가**를 선택하면 대상별 평가기준·점수·순위·추천의견·서명·PDF가 독립됩니다. 기존 한 번 평가·권별 평가 방식도 유지됩니다.

한 교과에 도서명이 여러 종류인데 권/학기 값이 하나뿐인 경우에는 평가 방식을 명시적으로 선택해야 합니다. 예를 들어 `학기=3`인 목록도 도서명에 따라 나눌 수 있습니다. 평가가 이미 시작된 선정 대상은 후보 구성을 보호하므로, 기존 평가를 진행 중인 교과의 선정 방식을 변경하려면 평가자료 초기화가 필요할 수 있습니다. 업데이트 전 스프레드시트를 백업하세요.

### 2026-09-29 추천의견 재확인·평가기준 순서 개선

r8에서는 추천의견 옆에 **재확인 필요**가 뜨면 변경된 항목을 보여줍니다. 기존 의견이 적절하면 **내용 확인 완료**를 눌러 문구와 서명을 유지한 채 안내를 해제할 수 있습니다. 의견을 실제로 바꿔 저장하면 추천의견서 서명은 다시 받아야 합니다.

평가기준을 추가하면 고정된 **교과용도서의 가격** 항목 바로 위에 들어갑니다. 각 평가기준의 위·아래 버튼으로 순서를 조정할 수 있고 가격 항목은 마지막에 유지됩니다. 평가기준 순서를 바꾼 뒤 저장하면 기존 정책대로 평가 서명을 다시 받아야 하므로, 가능하면 평가 시작 전에 순서를 확정하세요.

### 2026-09-23 업데이트 안내 배너

### 2026-09-22 수정 배포 안내

r6에서는 최초 설정에서 파일 업로드 없이 도서를 직접 추가하고 새 과목명을 입력했을 때 다음 단계로 넘어가지 못하던 문제를 수정했습니다. 도서·가격 단계에서 입력한 새 과목은 다음 단계로 이동할 때 교과협의회와 선정 단위에 자동으로 추가됩니다.

r5에서는 개인별 평가 PDF의 과목·위원·서명을 표 위에 배치해, 도서가 많아도 서명이 (인) 위에 보이도록 수정했습니다. 평가내용 작성용 서식에는 서명을 표시하지 않습니다. 가상 도서 10종과 TEST 서명으로 PDF를 확인했습니다.


r3에서는 최초 설정의 **교직원 파일 일괄 등록**을 고쳤습니다. 새 학교의 협의회 명단이 비어 있어도 `이름 / 교과 / 계정` 파일을 올리면 해당 교과 교사를 한 번에 등록하고 협의회에 연결합니다. 등록하지 않은 교과의 직원은 제외하며, 이미 등록된 교사는 아이디만 갱신합니다. 적용 후 교과부장·서식2 작성자를 지정하고 마지막 단계에서 **설정 저장**을 눌러야 반영됩니다.

이전 배포본의 최초 설정 기본값에 특정 학교의 교직원 명단과 역할이 포함되는 문제가 있었습니다. 이번 수정본은 **교직원·역할·도서·평가·추천의견이 빈 상태**로 시작합니다. 이전 ZIP은 새 설치에 사용하지 마세요.

이미 설치했다면 스프레드시트를 먼저 백업하고, 이번 ZIP의 Code.gs, Index.html, appsscript.json 전체를 각각 교체·저장한 뒤 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**를 선택하세요. 기존 initializeSchool을 다시 실행하거나 데이터 시트를 삭제할 필요는 없습니다.

최초 설정을 저장하지 않았다면 업데이트된 웹 앱을 새로고침해 확인하세요. 이미 저장한 명단은 학교 운영 데이터이므로 자동 삭제하지 않습니다. 남아 있는 명단은 담당자가 확인 후 수정해야 합니다. 과거 Git 기록, 이전 다운로드 및 제3자 사본은 최신 배포 교체만으로 제거되지 않습니다.

1. ZIP 압축을 풉니다.
2. `처음_시작하기.html` 파일을 더블클릭해 설치 순서를 확인합니다.
3. Google Apps Script에 `Code.gs`, `Index.html`, `appsscript.json` 세 파일을 넣습니다.
4. 학교 최초 설정과 웹 앱 배포를 마친 뒤, 각 선생님에게 웹 앱 주소와 본인 아이디를 개별 안내합니다.

> GitHub 링크는 프로그램을 받는 곳입니다. 링크를 누르는 것만으로 업무 프로그램이 실행되지는 않습니다. 각 학교 담당자의 최초 설치가 필요하며, 이후 선생님들은 해당 학교의 웹 앱에 접속합니다.

## 검증한 내용

r14는 기존 형식의 무손실 전환, 800만 문자 경계, 25개 대상·10명씩 서로 다른 서명 이미지, 중간 실패와 전환 실패, 충돌 및 다른 대상의 저장 보존을 모의 Google 저장 환경에서 검사했습니다. 최종 서버 파일로 직접 서명·이미지 첨부·반복 저장·새로고침을 로컬 브라우저에서 확인했습니다. r14·r13·r10·r9·r8 회귀 테스트가 통과했습니다.

새 저장 형식으로 복원한 가상 자료를 이용해 국어 3개·과학 5개 대상의 서식 1·2·3 PDF 총 40쪽을 다시 생성하고 대표 페이지의 대상명·표·서명을 확인했습니다. 실제 학교 Google Apps Script에 재배포해 검증한 것은 아니며 Google 장애나 모든 규모의 자료에 대한 무손상 보장을 의미하지 않습니다.

이는 모든 학교 정책·브라우저·입력 자료나 대규모 동시 접속을 보장한다는 뜻은 아닙니다. 학교별로 소규모 자료를 먼저 테스트하고, 실제 제출 전 서식·수치·서명을 확인하세요.

## 운영할 때 꼭 확인하세요

- **아이디 자체가 접근 수단입니다.** 아이디를 아는 사람은 그 계정으로 접속할 수 있습니다. 추측하기 어려운 값을 발급하고 개별 안내하세요.
- 웹 앱 주소·아이디 목록·평가자료·실제 서명은 공개하지 마세요. 학생 개인정보 등 민감한 자료를 입력하지 않습니다.
- Google 로그인을 요구하지 않는 교사 접속은 설치 시 익명 접근이 허용되어야 합니다. 학교 Google Workspace 정책에 따라 제한될 수 있습니다.
- 각 학교는 별도의 스프레드시트와 Apps Script에 설치합니다. 최신 설치 파일에는 학교 운영 명단을 기본값으로 넣지 않습니다. 이전 공개 기록에는 과거 버전이 남을 수 있습니다.
- 업데이트할 때는 같은 배포본의 Code.gs·Index.html·appsscript.json을 함께 교체하고 **배포 관리 → 새 버전**을 반영합니다. 기존 데이터 시트는 삭제하지 않습니다.
